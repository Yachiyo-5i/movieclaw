## movieclaw v0.7.0

Jellyfin 兼容层的一次体验修补：大库首页浏览再快一截、播放关窗后硬盘
终于能停下来，客户端里的「下载」按钮也真的能用了。

本版本**不需要更新 Docker 镜像**（runtime 仍为 3），在「设置 → 应用」
一键更新即可。

### 新增

- **Jellyfin 客户端的「下载」按钮可用了**：兼容层此前一直宣告支持内容
  下载，客户端也照着显示了下载按钮，但对应接口从未实现，VidHub 等客户端
  点下载只会 404、下载起不来。现补齐 `/Items/{id}/Download` 与
  `/Items/{id}/File`：
  - 本地文件直接回文件流，带断点续传（Range/206），文件名与库里一致
  - strm 条目与在线播放同策略——302 跳到云盘直链，下载流量不经过
    movieclaw，服务器零负担
  - 多版本条目可指定下载哪个版本，不指定就取第一个

### 改进

- **大库首页浏览继续提速**：1200+ 部电影的库在 VidHub 里打开时，
  `/Items`、`/Items/Latest`、`/Views` 会捎带加载大量用不上的数据。
  现在列表只取 DTO 真正需要的字段，演职员、媒体源等重字段按请求装载；
  「最新加入」与电影库分页改为在数据库里完成筛选排序分页，并为浏览
  热路径加了覆盖索引。库封面生成也不再水合整库元数据，同一个库的并发
  封面请求会复用同一次生成，不再重复扫描和重复渲染
- **后台扫描不再顺手批量探测历史文件规格**：实时监控、延迟补扫、定时
  对账默认跳过老文件的 `ffprobe`，避免机械硬盘被后台任务持续搅动。
  需要补齐规格时，在库里主动发起一次扫描即可，主动扫描仍是完整探测

### 修复

- **关掉播放窗口后硬盘还在响、CPU 降不下来**：客户端已经上报播放停止，
  服务端却可能留着没读完的 Range 请求继续读盘。现在按设备登记活跃的
  本地视频流，收到停止上报（含播放失败的停止）时主动掐断该设备的所有
  残留流；读取过程逐块检查取消状态，最多多读一个 64 KiB 块就收手。
  Range、206、HEAD 等播放语义保持不变

### 说明

- 数据库迁移向前兼容（仅新增索引，不改动已有数据），应用内更新支持
  一键回退（跨版本回退由更新前的自动备份兜底）
- Jellyfin 响应结构与字段语义未变，现有客户端无需任何调整
