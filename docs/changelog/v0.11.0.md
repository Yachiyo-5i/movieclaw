## movieclaw v0.11.0

这是一次围绕订阅自动化、下载可靠性与任务可观察性的功能升级。订阅现在能结合剧集播出
时间和 PT 站点资源规律预测下一次可用窗口，并在下载长期无进展时安全寻找替代资源；
下载中的已完成文件可提前进入整理流水线，任务中心也补齐了下载、入库与替换过程的完整
历史和操作入口。

### 新功能

- **资源发布时间预测**：按剧集播出计划、历史发布时间和站点时区生成单集资源窗口，
  在预计窗口内主动探测，减少新集上线后的等待时间；预测快照会持久化，重启后继续生效
- **无进展任务自动替换**：订阅下载在长时间没有有效进度时可重新搜索更健康的候选，
  替换过程记录尝试台账，并在清理旧任务前检查分享率、做种和 H&R 风险
- **下载中提前入库**：qBittorrent 与 Transmission 会暴露文件级完成状态；已完整下载的
  视频文件可先进入识别和整理，其余文件继续下载，失败与重试仍保持幂等
- **持续追新独立开关**：剧集订阅可单独控制是否追踪未来新集，不再与暂停当前追踪混为
  一谈；超出当前订阅范围的工单会退出自动化，但保留已有下载和任务历史
- **CLI 智能下载路由**：命令行搜索结果可直接进入下载目标预检与提交，统一复用媒体库、
  下载器和路径映射规则，并给出可读的路由选择与失败原因

### 改进

- **任务中心重设计**：下载、订阅和入库任务使用统一的分组、阶段、时间线与操作模型；
  增加移动端卡片布局、失败原因、入库历史、替换入口和长文本溢出提示
- **发现与搜索契约统一**：片单、影视搜索、详情、订阅和媒体库接口改用稳定引用与语义化
  operation ID，Web、CLI 与 Agent 共用同一套公开契约
- **时间统一为 UTC**：API 的时区感知时间统一输出 `Z`，PT 站点声明本地时区后再归一化；
  修复 CHDBits 等内置站点的历史发布时间偏移，并增强 TTG/M-Team 页面解析
- **下载状态更准确**：区分排队、校验、停滞、暂停和错误状态；进度心跳、做种状态与文件
  明细会持续刷新，避免把排队任务误判为卡死
- **完成内容核验**：已完成种子的文件清单若明确缺少承诺集数，只把缺失工单退回重找；
  全集包不再默认覆盖特别篇，避免订阅永久卡在等待不存在的文件
- **媒体库与订阅可靠性**：增强监听入库的部分完成、重复文件和重试处理；根路径对账、站点
  配置解析、滚动位置恢复及种子同步看门狗继续补强

### 升级说明

- 首次启动会新增资源预测、订阅下载尝试台账和追踪范围字段，并对内置站点的历史时间做
  一次性 UTC 修复；迁移只向前增加或修正数据，应用更新前仍会自动备份
- 本版本未改变 Python/Node 运行时依赖、Docker 基础镜像或入口契约，runtime 版本保持 7；
  现有 runtime 7 用户可直接使用应用内更新，也可以拉取 v0.11.0 镜像整体升级
- 若需要跨版本回退，请使用更新前自动备份恢复数据库，避免旧版本读取新迁移后的结构
