## movieclaw v0.7.1

Jellyfin 兼容层的一次协议对齐修补：对照真 Jellyfin 源码逐字段、逐端点
审计了下载与播放链路，修掉了「剧集下载得到 0 字节文件」这类翻车点。

本版本**不需要更新 Docker 镜像**（runtime 仍为 3），在「设置 → 应用」
一键更新即可。

### 修复

- **剧集层级不再出现会翻车的「下载」按钮**：条目此前不输出
  `CanDownload` 字段，VidHub 等客户端只能按全局策略放行，在整部剧上
  也显示下载按钮——点下去打到的是剧集条目的取流地址，得到 404 后存成
  一个打不开的 0 字节文件。现在对齐真 Jellyfin 语义：电影和单集为可
  下载（且文件在位才给），剧集和季恒为不可下载，客户端据此正确隐藏
  按钮，单集下载不受影响
- **文件全部丢失的剧可以手动标记已看了**：此前在客户端上对文件已丢失
  的剧集点「标记已看」会报错（404），真 Jellyfin 的语义是条目还在就
  允许标记。现在按元数据里的集清单级联标记
- **播放失败的上报不再被记成正常观看**：个别客户端上报播放停止时
  `Failed` 字段发的是字符串 `"true"` 而非布尔值，此前会被当成正常
  停止落库，把失败的播放记成观看进度。现在一并识别并跳过
- **季卡片显示集数角标**：季条目此前缺 `ChildCount` 字段（真 Jellyfin
  恒输出该季集数），部分客户端的季列表因此不显示「N 集」角标

### 改进

- **补齐真 Jellyfin 恒输出的条目字段**：`LocationType`、`VideoType`、
  顶层 `Container`，以及按需输出的 `Width`/`Height`/`IsHD`/`CanDelete`。
  客户端列表页的容器标签、HD 角标等信息因此完整
- **未实现的协议端点不再暴露业务错误格式**：客户端探测
  `/LiveStreams/Open`、HLS 等未实现端点时，此前会收到 movieclaw 业务
  层的 JSON 错误信封（最容易被识别出「不是真 Jellyfin」的地方），
  现在按协议惯例返回空 404/405
- 取流接口的 MIME 类型判定补齐 `?container=` 参数层级（对齐真
  Jellyfin 的优先级：URL 后缀 → container 参数 → 真实容器）
