## movieclaw v0.6.0

事件 Webhook 首发——播放、收藏、订阅动作可实时推给任意第三方（含
Jellyfin 插件兼容格式），外加大库浏览的性能重做与 11 个新 PT 站点。

本版本**不需要更新 Docker 镜像**（runtime 仍为 3），在「设置 → 应用」
一键更新即可。

### 新增

- **事件 Webhook（设置 → Webhook）**：把 movieclaw 里发生的事接出去，
  自动化播放通知、观影统计、家庭大屏联动等玩法不用再轮询接口：
  - 事件覆盖播放开始/暂停/继续/停止/播放进度/看完、标记已看与收藏、
    订阅开始下载与已入库；每个 endpoint 独立勾选想要的事件
  - 两种报文格式：movieclaw 自有协议（HMAC-SHA256 签名、统一信封）与
    **Jellyfin 插件兼容格式**——变量名与 jellyfin-plugin-webhook 一致，
    现成的 Handlebars 模板可直接粘过来，下游服务无需适配
  - 每个 endpoint 可单独选择局域网直连或走代理出站；投递失败按
    5s/30s 重试，最近 50 条投递记录在页面上可查，便于排错
  - 支持一键测试发送；签名密钥只在创建/轮换时明文展示一次，之后
    加密落库、读取打码
- **扫描后自动清理丢失记录（库级开关，默认关）**：自己在磁盘上删了片，
  扫描完台账不再留着一堆「丢失」记录要手动清。清理不可恢复（丢失记录
  是「重新下载」的输入、改名归并的候选池），所以默认关闭，需在库设置
  里明确打开；只在本轮扫描可信时才清理（遍历没有目录读不动、未被手动
  停止、挂载掉线的根整体跳过），扫描摘要会显示「清理丢失记录 N」
- **对话页支持改写某轮提问并从该处重发**：点用户气泡上的铅笔，二次确认
  后这一轮及其后的往返被永久删除、原文填回输入框，改完重新发送，Agent
  从截断处继续——上下文里不再残留被丢弃的内容
- **对话页复制按钮**：自己发的提问气泡、回答里的代码块都能一键复制
  （桌面 hover 浮现，触摸端点一下浮现）
- **11 个新 PT 站点**：hdsky、hdvideo、hhanclub、hdarea、hddolby、
  hdfans、hdtime、nicept、piggo、pttime、soulvoice（感谢社区贡献）

### 改进

- **大库浏览快了一个数量级**：1200 部电影的库在 VidHub 里打开要 22.8 秒
  的问题已修（issue #88）。确立「浏览零媒体 IO」原则——入库后除非主动
  扫描/刷新，浏览请求不再对媒体目录做任何文件系统调用（ETag、图片
  版本号、strm 直链改为落库或按需读取，演职员按需装载）。模拟云盘
  5ms/次延迟下，列表 DTO 构建从 19.9s 降到 0.08s，整条请求进入亚秒级。
  **注意**：详情页不再顺手补探媒体规格，未探测过的文件会提示重新扫描，
  扫描时统一回填
- **搜索图览模式海报卡重做**（issue #74）：文字从海报渐变上下沉到图外
  实底区（浅色海报不再糊成一片），新增剧集季/集 chip（「第 2 季 ·
  全 12 集」「第 1-3 季」等），一眼能看出是整季包还是单集
- **监听导入「已入库」统计补文件数**：剧集一个条目往往是一个季包，
  此前显示「已入库 3」会被读成只入了 3 集，现在展示为
  「已入库 3（14 个文件）」
- hdarea 请求间隔调大到 60s，应对站点限流

### 修复

- **站点设置页侧栏变白**（issue #89）：接入十几个站点后进入站点/搜索
  分类设置页，浏览器 WebGL 上下文超限会挤掉侧栏的液态玻璃面板，表现
  为左侧菜单整块变白且不再恢复。现按需创建/主动归还上下文，并支持
  上下文丢失后自愈重绘
- **镜像升级后误报「需升级镜像」**：升级镜像后 data 卷里遗留的旧版本
  overlay 永远不会再被采用，状态页却一直提示升级刚升级完的镜像。现在
  启动时自动清理这类残留（数据库备份保留），状态文案也区分「需升级
  镜像」与「为旧镜像构建，已停用」两种方向
- **跨盘布局下建不出 auto 硬链规则**（issue #79）：创建「自动路由 +
  硬链」规则时的同盘校验此前把所有库都纳入检测，导致「跨盘 strm 归档库
  + 硬链自动分流」这种标准布局被误伤。现在只检测自动路由真正可能选中的
  库（默认库 + 声明了收藏范围的库），报错文案也说明了每个库为什么进入
  候选
- Webhook 首发前的自查修复：格式切换后补发签名密钥（此前会静默发出无
  签名报文）、单个 endpoint 宕机不再拖垮其他 endpoint 的投递、Jellyfin
  格式订阅无对应事件时保存即拒绝
