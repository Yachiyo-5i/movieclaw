# 字幕/音轨识别 NER 化：SUBTITLE + AUDIO span 抽取方案

## 背景与动机

种子标题/副标题里的字幕信息目前由 `src/movieclaw_enrich/extractors.py` 的
6 条正则识别（1 条全局否定 + 1 条破坏性语境守卫 + 4 条正向模式），只输出
`zh-Hans` 单一值。这套正则已经历三轮修补（v12 首版 → `36a23f8` 修 6 类误报 →
`b81e20f` 补真实变体 → v13 修 3 类误报 + 4 类漏报），呈典型的打地鼠曲线：

- 否定、语境（字幕 vs 配音）、组合写法每种句式都要手写规则，词序稍变即失效；
- "无内嵌字幕，外挂简中"能识别对是巧合式规避（"无"与"字幕"中间隔了"内嵌"），
  没有机制保证；
- 守卫是破坏性 `sub("")`，被删文本对后续正则不可见，误杀不可观测；
- 测试集（54 例）全是已知病例的固化，野外新变体的漏报率从未被测量。

音轨维度（国语/粤语/原声语言）则完全没有识别。issue #104 要求选种规则支持
"中文字幕"维度——一旦识别结果进 matcher，误报=下错种子，对准确率的要求会
显著高于现在只做前端筛选的场景。

而项目已有一条被充分验证的路径：`ml/` 的 LLM 蒸馏 + 小模型多任务架构
（chinese-lert-small，int8 15MB，CPU p50 3.3ms），在更难的片名/季集任务上
做到逐字段 span F1 0.90-0.97。字幕/音轨识别本质是带否定、带语境、带跨段
推理的语义判断，恰好是正则的天花板、该架构的舒适区。

## 目标

1. 从 title + subtitle 中识别**字幕声明**与**音轨语言声明**，输出结构化的
   `subtitle_languages`（值域从单一 zh-Hans 扩展为完整 BCP 47 列表）、
   `subtitle_carriers`（内封/内嵌/外挂）与新字段 `audio_languages`。
2. 政策类判定（"中字"泛称不猜简繁、否定裁决）全部落在确定性代码里，
   改政策不需要重训模型。
3. 为 matcher 提供可靠的字幕/音轨过滤维度（issue #104）。
4. 现有 6 条字幕正则最终退役，字幕识别的错误从此流进 NER 已有的
   修复流水线（回归集 → 定向补样 → 重训 → 审计转正）。

## 非目标

- 不做音频**编码/声道**的模型识别（DDP/Atmos/5.1 是封闭词表，留在正则通道，
  这是双通道分工的刻意边界）；
- 不做运行时 LLM 推理（NAS 离线部署 + 毫秒级延迟 + 结果可复现的约束不变）；
- 不识别"双音轨/多规格音轨/评论音轨"等**无语言信息**的音轨数量词
  （没有语言就无法归入语言声明，消费端也无从消费）；
- 不从字幕组名推断字幕存在（"XX字幕组"是发布组信息，推断违反三态铁律；
  将来如需要，走 release_group 通道做显式政策）。

## 总体设计：span 圈定（模型）+ 微解析（代码）两层

延续 `movieclaw_enrich` 的分工铁律——**模型只圈 span，语义解析由确定性代码做**：

```
title/subtitle ──► NER 模型（span_head 13→17 类）
                     │  SUBTITLE span："内封简繁英SUP特效字幕"、"无字幕"、"中字"、"CHS"
                     │  AUDIO    span："国语"、"粤语音轨"、"国英双语"、"日语"
                     ▼
                  微解析器（纯函数，闭词表）
                     │  语言映射：简→zh-Hans 繁→zh-Hant 英→en 日→ja 韩→ko 中字→zh(泛称)
                     │            国语→cmn 粤语→yue
                     │  载体：内封→embedded-soft 内嵌→hardcoded 外挂→external
                     │  否定："无/没有/不含…字幕"、"字幕：无"、NO SUBS
                     │  裁决：显式否定 > 显式声明（跨段生效）；泛称政策在此拦截
                     ▼
                  TorrentAttrs
                     subtitle_languages: ["zh-Hans", "zh-Hant", "en"]
                     subtitle_carriers:  ["embedded-soft"]        （新增，可选）
                     audio_languages:    ["cmn"]                  （新增）
```

为什么是 span + 解析器而不是 document 级分类头：

| 维度 | 分类头 | span + 解析器（本方案） |
|---|---|---|
| 政策（泛称/否定裁决） | 训练目标，学不到 100%，改政策要重训 | 一行代码，精确、可单测 |
| 组合写法（简英/简繁英/国粤双语…） | 每种组合要训练数据 | 词表组合免费覆盖 |
| 可解释性 | 只有概率 | 每个结论带证据 span，错例可归因 |
| 新维度扩展（新语言/载体） | 加头+重标+重训 | 词表加一行 |
| 否定与语境 | 能学 | 同样能学（圈定即语境判断） |

模型承担的**唯一**智能任务：判断一段文字是否在谈论字幕/音轨（含把
"简体中文配音"从字幕声明中区分出去）。其余全部确定性。

## 标注规范 v12（PROMPT_VERSION 11 → 12）

在 v11 的 JSON 输出中新增两个子串列表字段：

- `subtitle_decl` → BIO 标签 `SUBTITLE`：字幕声明片段，整段抽出内部不拆。
  三类都抽：①肯定声明；②否定声明（"无字幕"、"字幕：无"含否定词整段）；
  ③泛称（"中字"——判断简繁不是标注任务）。
- `audio_decl` → BIO 标签 `AUDIO`：音轨/配音语言声明。两种形态：
  ①语言词+配音/音轨/语音（"国语配音"整段）；②独立成标签的语言词
  （"[国语]"、"*日语*"、"官方 国语 中字"里的"国语"）。

### 圈定十一则（四轮实测迭代产物，完整文本见 `ml/torrent_ner/annotate.py` v12 提示词）

1. 只圈语言/载体/有无，绝不圈音频编码与声道（"国语 DDP5.1" 只抽 "国语"）；
2. 连写标签拆轴："国语中字" → AUDIO "国语" + SUBTITLE "中字"；斜杠混排段按
   语义切（"国语/简繁英等多国软字幕" → "国语" 入 AUDIO，其余入 SUBTITLE）；
3. "双语"归轴看伴随词：含简/繁等**字形**词 → SUBTITLE（"简英双语"）；
   含国/粤或语种对且无字幕尾词 → AUDIO（"国粤双语"、"中英双语"）；
4. 字幕组/发布组名不是字幕声明（含"无字幕组水印"类谈水印的）；
5. 无语言信息的音轨数量/规格词不抽（"评论音轨"、"多规格音轨"、"2Audios"）；
   语言词在旁边时只抽语言部分（"英语+杜比全景声·多规格音轨" 只抽 "英语"）；
6. 信息栏语言元数据列表视为**原声语言声明**逐项抽（"| 日语 / 英语 / 粤语 |"
   抽三项）；紧邻的制片国家/地区绝不能抽；
7. 语言词必须是对本资源音轨/字幕的声明（片名/剧情简介里的语言字样不抽）；
8. 分隔符连写的多语言段**整段抽出**不拆单字（"国|英音轨"、"国粤英三语"
   整段一个值）——只有独立分隔的语言列表（"| 日语 / 英语 |"）才逐项抽；
9. 发行流程/来源词（原盘/DIY/官方/新增/独家/首发）不作 span 开头，值从第一个
   语言词或载体形态词开始（"原盘DIY简繁双语四字幕" 抽 "简繁双语四字幕"）；
10. 孤立形态词（标签堆叠里的裸"特效"/"内封"）不是完整声明不抽，
    与字幕词或语言词连写时才随整段入值（"特效字幕"、"内封简中"可抽）；
11. 零编造铁律不变：值必须能在原文逐字定位。

## 数据管线

### 存量与增量

- **存量 ~1.9 万条走 delta 标注，不做全量重标**：v12 未改动六个老字段的
  任何语义（四处增量全部只涉及新字段），老标签在 v12 下完全合法；存量
  唯一缺的是新字段（不补标会把"中字"教成 O 负监督）。用只含
  subtitle_decl/audio_decl 定义+十一则的短提示词补标两个新字段并合并
  进原记录。核心收益是**零扰动**：六字段监督与 R9 完全一致，新模型老字段
  指标的任何波动都可归因于新增两头本身，不掺标注器随机性导致的标签漂移。
  合并冲突用显式规则而非 resolve_overlaps（后者长度优先，会让"老片名误含
  标签词"的更长脏 span 压掉新声明，方向恰好相反）：新字段 span 必留，
  与之重叠的老 span 丢弃并打 review 送人工，validate.py 重叠校验兜底。
- **增量混采**：NAS 生产库（`ssh root@192.168.1.11` 容器内 sqlite backup 快照，
  勿直接拷带 WAL 的库文件；scp/rsync 均不通，用 ssh cat 管道）已积累 3 站
  5167 条（2026-08 实测）。声明密度分站差异大：chdbits 95%、ssd 50%、ttg ~2%。
  注意 chdbits 已在既有语料中（`ml/README.md` 示例 id 即 chdbits），
  依赖 sample.py 的 id+文本双重去重排掉重复；每站配额 400-600 与既有分层
  一致（净增约 1200-1800 条），避免 3 站稀释既有 17 站的写法多样性。
  混采只 append 不替换——稳定哈希切分保证新样本按比例流入 train/dev/test
  且不动老测试集。建议固化为每轮重训前的常规步骤，持续吃到最新分布。
- **稀有桶定向捞取**（mine.py 加桶，全量收不占站点配额）：无字幕/否定式、
  配音语境、外挂、评论音轨（负样本）、信息栏语言列表，以及 **ttg 的标题侧
  声明**（"粤语 | 无字幕" 写在主标题——现有语料的声明几乎全在副标题段，
  标题段正类能防止模型学出"声明只在 subtitle 段"的伪相关）——生产库实测
  这些桶天然稀少（无字幕 7/5167、配音 2/5167），必须定向配额。

### 混合策略：按"声明词汇域"配额（2026-08-10 实测诊断驱动）

NAS 5167 条的诊断揭示了两个决定混合策略的事实：

1. **声明密度类别差异巨大**：tv 72%/44%（字幕/音轨声明占比，富矿）、
   anime 59%、documentary 59%、movie 23%（天然负样本来源）、music 6%。
2. **声明词汇按 类别×发布文化 几乎不相交**："簡繁DVB字幕" 全在港剧、
   "硬字幕" 97% 在国产剧（CMCTV 风格）、"原盘DIY四字幕" 几乎全在电影、
   "简日双语/字幕组" 词汇域在 NAS 三站为**零**（活在 M-Team 系动漫站）、
   综艺在站点分类中不存在（藏在 tv 里，"期"形态仅 ~70 条）。

因此多样性的正确单位是**声明词汇域**（类别与发布文化的组合），漏掉一个域
= 模型对该域词汇全盲。已识别的域清单：国产剧硬字幕域 / 港剧粤语DVB域 /
原盘DIY电影域 / 动漫简日字幕组域（NAS 缺失）/ 综艺期域 / 纪录片双语域 /
演唱会无字幕域 / 无声明负样本域。

**混合配方（重标时执行；文献 × 项目实证对齐版）**：

规模目标 **25-30k**：学习曲线实证（50%/75%/100% → F1 0.795/0.843/0.873）
在 15k 仍未饱和；按实测标注吞吐约 5-6 小时双引擎预算，可承受。

1. **域配比用温度采样 τ=2（平方根缩放），不用均匀配额也不用自然分布**。
   文献结论（Upsample or Upweight, arXiv:2410.04579）：按自然比例采样欠拟合
   小域，极端过采样小域又过拟合；τ≈2 是标准折中。规则：
   `p_域 ∝ sqrt(n_域)`，再叠两个硬约束——每域 floor ≥400（不足则全量收
   + augment 合成补），单域 cap ≤25%。按此推算类别轴目标大致为：
   国产剧 ~20% / 电影 ~20% / 动漫 ~15% / 港剧粤语 ~8% / 纪录片 ~7% /
   综艺 ~6% / music+other ~5%，另留 **15-20% 真实分布随机锚**
   （保护两个分类头的先验不被配额扭曲）。
2. **复制过采样是最后手段且 cap ×5**（collection ×5 先例 + 文献的小域
   过拟合警告）：稀缺域优先真实补样 > augment 合成 > 复制。
3. **负样本三层，合计 ~20-25%**（UniversalNER 实证 negative sampling
   显著提升蒸馏效果，arXiv:2308.03279）：
   ①无声明普通影视 ~15%（教沉默）；②硬负样本每形态 ≥100 条——配音/
   音轨语境、字幕组水印、SUP-in-word（augment 与正样本**成对**造）；
   ③非影视样本 5-8%（沿用现有负样本机制）。
4. **质量分层：金标测试集 + 规模训练集**（标注噪声文献共识：质量 > 数量，
   集成一致性过滤有效）：
   - dev/test 切分（稳定哈希的 20%）**双引擎标注 + 分歧全量人工裁决**
     → 金标层，评估永远打在金标上；
   - train 切分单引擎为主 + 8-10% overlap 抽检；双引擎分歧样本进 review
     隔离（dataio clean_only 已支持），裁决前不入 clean 训练集；
   - augment 合成只进 train（现行规则不变）。
5. **类别识别用 R9 预打伪标签**（3.3ms/条，mine.py 现成基础设施）：
   站点分类口径不一且缺综艺，抽样分层一律以模型伪标签为准，站点分类
   仅作交叉参考。
6. **域内词形均衡**：内封/内嵌/外挂/硬/SUP/DVB/简日/简韩/否定式/
   信息栏列表 每词形 ≥150-300。
7. **闭环**：evaluate.py 增加分类别/分域切片 F1，每轮训练后按短板域回调
   配额——最优比例不是先验常数，是迭代收敛点。v10 动漫专项（anime 召回
   85%→92.6% 靠补 1600 条）就是这个闭环的事后版，本策略把它前置。
8. **训练侧维持现状**：loss 不加权（项目实证 + 温度采样文献："upsample
   与 upweight 等损失，upsample 收敛更快"——我们在数据侧完成再平衡，
   loss 侧无需重复）；15 epoch、lr 5e-5 不动。

**当前 NAS 语料的域缺口清单**（17 站池恢复或生产实例加站后必补）：
动漫简日双语/字幕组域（0 条）、外挂域（4 条）、综艺期域（~70 条）、
无字幕否定域（7 条）。

### 合成增强（augment.py 新增变换，标签绝对正确）

- `dub_vs_sub` 成对注入：同一样本分别注入"简中字幕"/"简中配音"，
  强迫模型只能靠尾词定轴（替代现行正则的负向前瞻守卫）；
- `sub_negation`：注入"字幕：无"、"无字幕"变体；
- `audio_tag`：注入"[国语]"、"[粤语]"独立标签；
- `commentary`：注入"评论音轨"（不打标签，负监督）。

## 模型与训练

- `labels.py`：`FIELDS` 末尾追加 `SUBTITLE`、`AUDIO`（保持旧 id 稳定），
  BIO 13→17 类；`FIELD_PRIORITY` 中两者排在结构化字段之后、片名之前
  （与片名重叠时字幕/音轨标签胜出——片名精修本就要剥离标签词）。
- validate.py / dataio / encoding 遍历 `FIELDS`，自动兼容，无需改动。
- 训练超参不变（lert-small / 15 epoch / lr 5e-5）；新字段样本量足够
  （关键词密度 47%）不需要过采样，稀有形态靠定向桶与合成增强补。
- 评估：evaluate.py 自动纳入新字段的 span 精确匹配 P/R/F1；
  现有 54 个正则测试样例全部转入回归集 `ml/data/regression/cases.jsonl`
  作为转正门禁（含"简繁双语配音，内封英文字幕"等历史病例）。

## 运行时

### 推理与解析

- `inference.py`：BIO 解码/置信度门槛复用现有逻辑；SUBTITLE/AUDIO 不参与
  `_normalize_spans` 的号码类吸附。

## 训练过程复盘：十条可复用经验

1. **规范先收敛，语料后放量**。v12 只迭代 1.5 轮就放量 21k，v13 的 11 条
   规则事后才从分歧里挖出，代价是 17.9k 重标。已固化为强制流程（见下节）。
2. **标注分歧 = 模型难样本**，实证相关（分歧组 F1 低 8-45 点）：分歧样本
   不是垃圾是矿脉——裁决后回训练集、进回归集；一律隔离等于"删难留易"
   （审计实测稀有桶隔离率一度 80-100%）。
3. **分歧消解走成本金字塔**，逐层过滤后才动用贵裁判：确定性归一（1,700+
   假分歧）→ 变体超集规则（154）→ 判决模式化后机器采纳（胜率 ≥90% 的字段
   直接采优势方，4,460 案零成本）→ LLM 裁决分级（金标层独立双轮，train 层
   只裁目标字段）→ 残余 review。最终 LLM 只裁了全部分歧的 ~1/3。
4. **版本噪声比引擎噪声大**：同引擎 v12→v13 重标 diff 达 18.4%（3,286 条）。
   规范升级后，旧版本侧用富余额度全量重标比"混着裁"便宜且干净。
5. **裁决轮次必须真独立**：同 payload 跑两轮测的是模型自我一致性（93.8%），
   换 A/B 排列+乱序后真实一致率 86.4%。判决日志要带 win_spans 做可重放
   事实源，任何中断零丢失。
6. **dual_agreed ≠ 金标**：两个 LLM 一致可能是共同盲区，label_status 四级
   （single/dual_agreed/llm_adjudicated/human_adjudicated）显式建模可信度；
   评估集三件套（gold test / site holdout / temporal shadow）+ test 只跑一次。
7. **选模型不能看全局 F1**：s42 全局最低但目标字段精度最高。分层规则：
   老字段无回退一票否决 → 目标字段 precision → 宏 F1。多种子（σ 报告）
   把"回归 case 翻转"从掷骰子变成统计判断。
8. **切分按内容不按 id**：跨站转载同一 release 会泄漏 train/test（实测
   25 组），内容指纹分组切分；重叠 span 在 encoding 层硬报错，杜绝
   "落盘标注≠入训标签≠评估 gold"三态漂移。
9. **审计门前置**（corpus_report --strict）：队列配比 ≠ 成品配比，review
   隔离非均匀、去重、失败都会漂移；类别 τ=2 落点、词汇域 floor、负样本
   分层、分桶隔离率，违约不训练。
10. **额度工程化**：吞吐实测定并发（codex 12/claude 8/裁决 batch30×8）、
    熔断+探针自愈、断点续标/续裁幂等、贵模型只干裁判活、机械活给便宜引擎
    ——两天 5 万+ 标注/裁决调用全程无人值守跑完。

## 标注方法论：规范变更的强制迭代流程（v13 学费换来的教训）

v12 放量 21k 之后才从分歧中挖出 v13 的 11 条规则，代价是 17.9k 重标 +
数千案裁决。根因：门控 1 只验证了引擎间一致率，没走完
"分歧→裁决→规范增量→复测"的完整循环就放量。此后任何规范变更（v14+）
**必须**执行：

1. 新规范试标 500-1000 条（分层覆盖全部词汇域桶）；
2. 双引擎交叉 diff → fable 双盲裁决分歧 → 分歧模式聚类；
3. 可泛化的病灶写成规范增量条款，回到第 1 步复测；
4. **冻结条件**：新批次分歧率 ≤2% 且残余分歧无政策含义（纯噪声）——
   达到即冻结规范、放量标注；未达到不得放量；
5. 刻意不做"每批都改规范"的无限迭代：规范微版本碎片化的跨版本标签噪声
   比分歧本身更难清洗，收敛即冻结。

## 附录：v12 提示词增量原文（实测收敛版，并入 annotate.py 时逐字使用）

v12 相对 v11 的全部增量共四处，其余文本保持 v11 原样：

**① 字段列表新增两条**（episode_total 之后）：

```
- subtitle_decl: **字幕声明片段**列表——原文中谈论字幕的连续片段，每段**整体**抽出、
  内部不拆（"内封简繁英SUP特效字幕" 整段一个值）。三类都要抽：
  ①肯定声明（"简体中文字幕"、"简繁字幕"、"硬字幕"、"SUP字幕"）；
  ②否定声明（"无字幕"、"字幕：无"——含否定词整段抽出）；
  ③泛称（"中字"、"中文字幕"——不确定简繁也照抽，判断简繁不是你的任务）
- audio_decl: **音轨/配音语言声明片段**列表——两种形态：
  ①语言词+配音/音轨/语音字样（"国语配音"、"粤语音轨" 整段抽出）；
  ②独立成标签的语言词（"[国语]" 抽 "国语"、"*日语*" 抽 "日语"、
  "官方 国语 中字" 抽 "国语"、"粤语中字" 抽 "粤语"）
```

**② 新增"字幕/音轨圈定十一则"块**（字段列表之后）：

```
字幕/音轨圈定十一则：
- 这两个字段只圈**语言/载体/有无**，绝不圈音频编码与声道：DDP5.1、DTS-HD MA、Atmos、
  AAC、FLAC、2.0、5.1 等技术词一个都不能入，即使它们紧贴语言词（"国语 DDP5.1" 只抽 "国语"）；
- 连写标签拆轴："国语中字" → audio_decl 抽 "国语"、subtitle_decl 抽 "中字"；
  斜杠混排段按语义切："国语/简繁英等多国软字幕" → "国语" 入 audio_decl、
  "简繁英等多国软字幕" 入 subtitle_decl；
- "双语/双字幕"归轴看伴随词：含简/繁等**字形**词的是字幕（"简英双语"、"简繁双语四字幕"
  → subtitle_decl）；含国/粤或语种对且无字幕尾词的是音轨（"国粤双语"、"中英双语"、
  "国日双音轨" → audio_decl）；两轴证据同时出现时各归各轴分开抽；
- 字幕组/发布组名不是字幕声明："XX字幕组"、压制组后缀不入 subtitle_decl
  （"包含字幕组水印"谈的是水印也不入）；
- **不含语言信息**的音轨数量/规格词不抽："评论音轨"、"多规格音轨"、"双音轨"、
  "2Audios/3Audios" 都没有语言，无法归入语言声明；语言词在旁边时只抽语言部分
  （"英语+杜比全景声·多规格音轨" 只抽 "英语"）；
- 信息栏的语言元数据列表视为**原声语言声明**，逐项抽入 audio_decl
  （"| 日语 / 英语 / 粤语 |" 抽 "日语"、"英语"、"粤语" 三项）；
  紧邻的制片国家/地区（"日本 / 马来西亚"）是国家不是语言，绝不能抽；
- 语言词必须是对**本资源音轨或字幕**的声明才抽：片名里的语言字样（"粤语残片修复计划"）、
  剧情简介里的语言描述不抽；
- 竖线/斜杠等分隔符连写的多语言段**整段抽出**，绝不拆成单字或单项
  （"国|英音轨" 整段一个值，不拆 "国" 和 "英音轨"；"意大利|英音轨" 同理；
  "国粤英三语" 整段）——只有独立分隔的语言列表（"| 日语 / 英语 |"）才逐项抽；
- 发行流程/来源词不作 span 开头：原盘、DIY、官方、新增、独家、首发等词不入值，
  值从第一个**语言词或载体形态词**（内封/内嵌/外挂/硬/软/特效/SUP）开始
  （"原盘DIY简繁双语四字幕" 抽 "简繁双语四字幕"、"新增简繁双语特效字幕"
  抽 "简繁双语特效字幕"）；
- **孤立的形态词不抽**：特效/内封/内嵌/外挂/硬/软 单独出现（如标签堆叠
  "官方 中字 特效 …"里的裸"特效"）时不是完整声明，不抽；它们只有与字幕词
  或语言词**连写**时才随整段入值（"特效字幕"、"内封简中"可抽）；
- 这两个字段同样受零编造铁律约束：值必须能在原文逐字定位，抽不出就给空列表。
```

   （只输出两个新字段，合并进原记录）

3. **门控 1**：试标 500 条（存量 delta + NAS 新样本混合分层），双引擎全量
   crosscheck，分歧率 ≤ 历史水平（5-10%）方可放行；规范空白走 v12.x
   增量澄清（已标部分无需重标）
4. **门控 2**：稀有桶 + ttg 标题侧声明定向批（1-2k）——规范压力最大的样本
   提前消化；随后**冒烟训练**一轮验证 delta 合并/17 类 BIO 编码/
   FIELD_PRIORITY 管线端到端无系统性 bug
5. 主体批量：双引擎按不相交切片分工（并发实测见下，codex --workers 12 约
   81 条/分、claude --workers 8 约 27 条/分，合计 ~108 条/分，2 万条约 3 小时），
   另留 8% 共同切片做 crosscheck；每 tranche 跑 validate.py + 分布统计
   （含新字段 span 的样本占比应落在 40-50%，偏离报警）；长跑靠熔断
   （--max-consecutive-failures）兜住额度/登录态失效。
   `augment.py` 四个新变换同期实现
5a2. **原始标注不可变**：每个标注批次（引擎×规范版本）完成后立即归档
   `ml/data/labeled/raw-archive/<时间戳>-<文件名>`，此后一切清洗/归一/裁决
   只在派生副本上执行——原始态永远可回溯，清洗逻辑靠程序按记录内的
   `prompt_version`/`annotator` 戳分版本处理，出错可从任意归档点重放。

   Tier 0 `normalize_labels.py` 确定性归一（Complete/日期串年份/档期/地区
