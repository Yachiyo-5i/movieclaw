# Torrent NER 字幕/音轨模型训练计划审查意见

> 审查日期：2026-08-11  
> 审查对象：`docs/design/subtitle-audio-ner.md`、`ml/torrent_ner/` 训练管线、
> 当前本地标注语料与 C1 模型产物  
> 本文是训练前审查记录，不代表已经完成代码整改或模型转正。

## 1. 结论摘要

整体技术路线是正确的，值得保留：

- 使用小模型只圈定 span，语言、载体、否定和冲突裁决交给确定性微解析器；
- 使用真实分布锚点、词汇域配额、稀有桶和成对合成样本控制数据分布；
- 保留 R9 作为现役基线，通过同尺对比、回归集、野外验证和护栏审计决定是否转正；
- C1 虽然新字段指标较高，但因为老字段和域覆盖不稳而不转正，这个决定是正确的。

当前不建议直接启动正式 v2 训练。需要先解决三个 P0 阻塞项：

1. 当前测试集并不满足设计文档所定义的“金标”标准；
2. 正式语料仍有重叠 span，平面 BIO 无法无损表达，训练时会静默丢标签；
3. SUBTITLE/AUDIO 的野外验证、护栏审计、分域评估和回归门禁尚未真正闭环。

正式候选池已经达到约 2.64 万条、覆盖 17 个站点，当前最值得投入的不是继续
扩大标注量，而是提高金标可信度、修正切分方法，并让转正门禁真正可执行。

## 2. 审查时的实测状态

### 2.1 C1 数据与模型

当前 `ml/data/labeled/annotations.jsonl`：

- 总计 5,158 条，clean 4,985 条；
- train/dev/test = 4,148 / 485 / 525；
- 只覆盖 chdbits、ssd、ttg 三个站点；
- 525 条 test 中仅 66 条做过双引擎标注，51 条 `dual_agreed`，459 条为单引擎标注；
- 语料结构校验通过，没有重叠 span 或重复 ID。

C1 int8 ONNX 在 clean test 509 条上的字符 span 精确匹配指标：

| 字段 | Precision | Recall | F1 | Gold span 数 |
|---|---:|---:|---:|---:|
| TITLE_ZH | 0.960 | 0.971 | 0.965 | 619 |
| TITLE_EN | 0.896 | 0.924 | 0.910 | 699 |
| YEAR | 0.965 | 0.988 | 0.977 | 422 |
| SEASON | 0.972 | 1.000 | 0.986 | 382 |
| EPISODE | 0.978 | 0.962 | 0.970 | 234 |
| EPISODE_TOTAL | 1.000 | 1.000 | 1.000 | 50 |
| SUBTITLE | 0.992 | 0.994 | 0.993 | 356 |
| AUDIO | 0.959 | 0.969 | 0.964 | 195 |

分类轴指标为 media_type 0.996、content_type 0.933；CPU int8 延迟 p50 4.5ms、
p95 7.5ms。

这些结果证明新任务可以被当前架构学到，但不能直接当作最终转正证据：测试集主要
来自单引擎标注，并且只覆盖三个站点。尤其 AUDIO precision 0.959 对展示功能可能
已经可用，但对“根据音轨自动选种”的高代价场景仍然偏低。

### 2.2 正式多站语料

`work-codex.jsonl` 与 `work-claude.jsonl` 各有 21,274 条，覆盖 17 个站点；与
5,158 条 NAS 语料的 ID 没有交集，合并后共 26,432 条。合并候选集的最大单站占比
约 17.8%，规模和站点覆盖已经达到原计划目标。

当前仍有以下未收口项：

- 两份正式标注还有 1,380 条样本存在至少一个字段分歧，整条完全一致率 93.5%；
- 分字段剩余分歧：SUBTITLE 502 条（2.4%）、AUDIO 343 条（1.6%）、
  TITLE_EN 260 条、TITLE_ZH 176 条，其余字段更少；
- `work-codex.jsonl` 结构校验仍有 31 条样本失败，共发现：
  - TITLE_EN 与 TITLE_ZH 重叠 24 处；
  - EPISODE 与 SEASON 重叠 10 处；
  - AUDIO 与 SUBTITLE 重叠 1 处；
- 按当前 ID 哈希切分，合并候选集中存在 34 组、71 条归一化后近乎相同的文本
  跨越 train/dev/test；
- 合并候选集无 SUBTITLE/AUDIO span 的样本约 38.2%，高于文档期望的 20%～25%，
  也高于 `corpus_report.py` 当前接受的 15%～35%。

38.2% 负样本不一定意味着必须机械删减。自动选种更重视 precision，较多负样本可能
有价值；问题在于目前只统计了总比例，没有分别量化普通负例、硬负例和非影视负例，
无法判断多出来的负样本是否提供了有效监督。

## 3. 值得保留的设计

### 3.1 span 圈定与微解析器分层

模型负责判断文本是否在声明字幕或音轨，代码负责：

- BCP 47 语言映射；
- 内封、内嵌、外挂等载体解析；
- 否定优先级；
- 泛称政策；
- 多个声明之间的确定性裁决。

这种分工能够把业务政策从模型权重中剥离，政策变化不需要重新训练，同时保留证据
span，便于回归和错误归因。它比 document 分类头或继续堆正则更适合当前任务。

### 3.2 分域采样与稀有桶

按发布文化和词汇形态组织数据，比只按 movie/tv/anime 分类更贴近模型实际面对的
分布。国产剧硬字幕、港剧粤语 DVB、原盘 DIY、动漫字幕组、综艺期号等域确实存在
明显词汇差异，应继续保留域 floor、单域 cap 和真实分布锚点。

### 3.3 R9 不动、候选模型挑战基线

R9 继续服役，候选模型只有同时满足老字段无回退、新字段达标、回归通过、野外通过
才转正，是正确的风险控制方式。C1 没有因为总体 F1 较高就上线，说明当前策略已经
具备必要的保守性。

## 4. P0：正式训练前必须解决

### 4.1 建立真正可信的 gold dev/test

设计文档要求 dev/test 双引擎标注并对分歧全量裁决，但当前工具把
`dual_agreed` 称为金标。它实际只表示两个标注器给出相同结果，不表示结果被人工
确认；一致的系统性错误也会被保留。

建议将质量来源显式建模，不再用单个布尔值混合不同可信度：

| `label_status` | 含义 | 允许用途 |
|---|---|---|
| `single` | 单引擎标注 | train 规模层 |
| `dual_agreed` | 两引擎独立一致 | train；可作一般 dev 素材 |
| `llm_adjudicated` | 分歧经独立第三裁判定案 | train/dev；普通 test 素材 |
| `human_adjudicated` | 人工确认 | 正式 test、关键回归、困难桶 |

建议冻结三套评估集：

1. **gold test**：全部双标，所有分歧裁决；关键困难桶人工确认；版本发布后不再改；
2. **site holdout**：至少留出一个完整站点，验证发布文化迁移；
3. **temporal shadow**：来自训练数据时间点之后的新种子，验证真实分布漂移。

调模型和阈值时只看 dev。正式 test 只在最终候选上运行一次，避免通过多轮试验逐渐
过拟合测试集。

### 4.2 消除重叠标签，不允许训练阶段静默裁剪

当前模型是单标签平面 BIO，同一个 token 不能同时属于 TITLE_ZH 和 TITLE_EN，
也不能同时属于 SEASON 和 EPISODE。`resolve_overlaps()` 的长度优先规则会把另一条
监督静默丢掉，导致落盘标注、实际入训标签和评估 gold 三者不一致。

不建议为了 31 条样本升级成多层或多标签 NER，成本和运行时复杂度不值得。更简单的
方案是为重叠形态补充确定性标注政策：

- `SPY×FAMILY间谍家家酒` 等混合片名明确选择一个完整轴，另一轴只能标注不重叠别名；
- `E01-S01E05` 明确 season 与 episode 的切分边界，不标互相包含的 span；
- `简繁国语中字` 按字幕/音轨轴拆成互不重叠的最小连续证据；
- 无法按规则自动处理的样本进入人工 review。

管线要求调整为：

1. 标注定位阶段发现重叠即 review；
2. canonicalization 阶段按已测试规则处理；
3. encoding 阶段仍发现重叠就抛错，不再自动选一个；
4. `validate.py` 结构问题必须为 0 才允许训练。

### 4.3 让四道转正门禁真正支持新字段

当前文档写出的门禁方向正确，但实现还不完整：

- `wildcheck.py` 的字段集合和解析映射没有 SUBTITLE/AUDIO；现有逻辑遇到新字段
  会访问不存在的映射；
- `guard_audit.py` 目前只审计 YEAR，尚未实现字幕正则否定护栏的四象限；
- `evaluate.py` 只输出全局逐字段指标，没有站点、类别、词汇域、来源段切片；
- 文档要求的 `ml/data/regression/cases.jsonl` 当前不存在；
- 尚无对 `lang_decl.py` 最终语言集合的端到端评估。

建议先补齐这些评估工具，再开始昂贵的正式训练。否则模型训练完成后仍无法按原计划
判断它是否安全上线。

## 5. P1：强烈建议调整

### 5.1 从“按 ID 切分”改为“按内容组切分”

不同站点可能转载同一个 release，但拥有不同 ID。当前 `(site_id, torrent_id)` 哈希
不能阻止近重复内容跨切分，单次抽样里的精确文本去重也无法覆盖后续 append 和多轮
语料合并。

建议为每条记录生成仅用于分组的内容指纹：

1. 对 title/subtitle 做 Unicode NFKC；
2. 大小写折叠；
3. 统一空白和常见场景分隔符；
4. 对归一化后的 `(title, subtitle)` 计算 fingerprint；
5. 同一 fingerprint 的全部站点记录作为一个 group；
6. 对 group hash 切分，而不是对样本 ID 切分。

可以保留原始文本，不要用归一化文本训练；fingerprint 只负责防止泄漏。

### 5.2 改进 checkpoint 选择指标

当前 `train.py` 使用 seqeval 全局 F1 选择最优 epoch。高频 TITLE/YEAR 实体会掩盖
SUBTITLE/AUDIO 或小域退化，而且 token 级 seqeval 与线上字符 span、置信度门槛和
微解析器口径不同。

建议 checkpoint 选择采用分层策略：

1. 老六字段任一字段明显回退的 checkpoint 直接排除；
2. 在剩余 checkpoint 中优先比较 SUBTITLE/AUDIO precision 和宏平均 span F1；
3. 再看最差站点、最差词汇域和分类轴；
4. 最终用运行时同路径的端到端指标决定候选。

不必马上重新设计 loss。先让数据采样和模型选择指标正确，再根据训练曲线决定是否需要
字段加权，能避免过度工程。

### 5.3 最终配置至少验证三个随机种子

当前 R9 与 C1 基本是单次训练对比。TITLE_EN -0.012 既可能来自数据不足，也可能包含
随机初始化和批次顺序造成的方差。

建议保留 lert-small、15 epoch、lr 5e-5 作为基线配置，不做大规模超参搜索，但最终
配置至少跑 3 个随机种子：

- 用 dev 复合指标选择一个部署候选；
- 报告三个种子的均值、标准差和最差值；
- test 只评最终选择的一个候选，不能用 test 从三个种子里挑模型。

### 5.4 增强裁决轮次的独立性

当前 `adjudicate.py` 的两轮裁决使用同一模型、相同 prompt、相同批次和相同 A/B
排列。若模型推理较确定，两轮一致主要证明模型会重复自己，不能充分证明判决可靠。

建议：

- 第二轮交换 A/B；
- 改变 case 顺序和批次上下文；
- 记录每轮完整判决理由；
- dev/test 使用不同模型作第三裁判，关键困难桶进入人工终审；
- 若两轮或两模型不一致，不要自动选择主标注器，继续保留 review。

## 6. P2：建议同步修正文档与审计口径

### 6.1 v12 delta 的因果结论已不再成立

v12 只新增两个字段时，“老字段完全不动，因此老字段指标波动只能来自新增标签头”是
成立的。但 v13 已修改 YEAR、SEASON、TITLE、EPISODE_TOTAL 等老字段语义，并对
大量存量数据做了归一和重标。

因此正式 v2 的老字段差异同时受到以下因素影响：

- 新增 SUBTITLE/AUDIO 标签；
- v13 老字段规范变化；
- 新站点和新分布；
- 裁决和清洗；
- 训练随机性。

建议删除“delta 保证纯因果对比”的表述。若需要隔离变量，可额外训练一个
“R9 语料 + 只补两个新字段”的消融候选，但它不必成为发布候选。

### 6.2 负样本应按用途分层，不只看总比例

建议分别报告：

- 普通影视无声明负例；
- 字幕组、水印、SUP-in-word、评论音轨等硬负例；
- 非影视域外负例；
- 有字幕声明但无音轨声明，以及反向情况；
- title 段和 subtitle 段负例。

最终比例应由 dev precision/recall 曲线和真实线上 base rate 决定。20%～25% 可以作为
初始配方，15%～35% 可以作为报警区间，但不应在没有分层指标时机械删样本。

### 6.3 修正文档漂移

当前 `ml/README.md` 仍有六字段、13 类、PROMPT_VERSION=3、训练代码尚未多头化等
过时描述；设计文档的实施清单仍写 PROMPT_VERSION=12，但代码已经是 v13。

这些内容不会直接降低模型指标，却很容易让下一位执行者使用错误命令或错误判断数据
兼容性。建议在正式训练前统一更新为当前事实。

## 7. 建议增加的端到端指标

span F1 仍然需要保留，但它不足以衡量 matcher 风险。两个边界不同的 span 可能经过
解析器得到相同语言集合；反过来，一个看似只差少量边界的错误也可能触发错误语言。

建议同时报告以下指标：

### 7.1 模型层

- 每字段字符 span exact P/R/F1；
- 每字段支持数和 95% 置信区间；
- title/subtitle 来源段切片；
- 站点、内容类型、声明词汇域切片；
- 原始模型、int8 ONNX 和线上解码路径的一致性。

### 7.2 微解析器层

- `subtitle_languages` 集合 exact match；
- `audio_languages` 集合 exact match；
- `subtitle_carriers` 集合 exact match；
- 否定裁决准确率；
- 泛称、简繁、国语、粤语等单类 precision/recall；
- span 边界不同但解析结果等价的比例。

### 7.3 业务层

- 要求中文字幕时的错误放行率；
- 要求某音轨语言时的错误放行率；
- 未声明资源被错误当作已声明的比例；
- 自动选种与只展示筛选分别使用的 precision/coverage。

自动选种的错误成本明显高于前端展示，建议使用不同阈值。初始 matcher 门禁可以设为：

- 端到端语言判定 precision ≥0.98；
- 关键硬负例 FPR 的 95% 置信上界 <1%；
- 老六字段对 R9 无确定性回退；
- 所有固定回归用例通过；
- site holdout 和 temporal shadow 无明显崩塌。

具体阈值应在 gold dev 上校准，不能直接用 test 调参。

## 8. 推荐的正式执行顺序

### 阶段 A：冻结标注规范

1. 完成剩余 1,380 条样本的字段分歧裁决；
2. 聚类剩余分歧，确认没有新的政策空白；
3. 消除全部重叠 span；
4. `validate.py` 必须零错误；
5. 冻结 PROMPT_VERSION=13，训练完成前不再修改标注语义。

验收：新批次 SUBTITLE/AUDIO 分歧均 ≤2%，且残余分歧不包含政策含义。

### 阶段 B：构建 canonical corpus

1. 合并 5,158 条 NAS 和 21,274 条多站语料；
2. 按内容指纹全局去重、分组切分；
3. 保留原始标注不可变，canonical 文件由脚本重放生成；
4. 给每条记录写入质量等级和裁决来源；
5. 审计站点、类别、词汇域和分层负样本分布。

验收：无 ID/内容泄漏、无结构错误、17 站覆盖、单站 ≤25%，所有稀有域达到经过
复核的最低支持数。

### 阶段 C：冻结评估资产

1. gold dev；
2. gold test；
3. site holdout；
4. temporal shadow；
5. 54 条历史正则病例和新发现困难样本组成的 regression cases；
6. SUBTITLE/AUDIO 的端到端解析 gold。

验收：测试资产与训练语料内容去重，所有测试记录具备可审计的 gold 来源。

### 阶段 D：补齐评估工具

1. `evaluate.py` 增加分站、分域、来源段和置信区间；
2. `wildcheck.py` 支持 SUBTITLE/AUDIO 及微解析结果；
3. `guard_audit.py` 实现字幕否定护栏四象限；
4. `compare_models.py` 同时支持原始模型对比与线上完整路径对比；
5. 回归集命令失败时返回非零退出码，便于接入流水线。

验收：四道转正门禁可以从头运行并给出明确通过/失败结果。

### 阶段 E：正式训练

1. lert-small、15 epoch、lr 5e-5 作为基线；
2. 跑 3 个随机种子；
3. 按 dev 复合指标选择候选；
4. 导出 int8 ONNX 后重新跑全部 dev 门禁；
5. 最终候选只跑一次 frozen test。

### 阶段 F：影子上线与转正

1. 保持 R9 对外提供结果；
2. v2 在 shadow 模式记录新字段、正则护栏冲突和 matcher 决策差异；
3. 一个完整版本周期内审计生产分布；
4. 达到 precision/FPR 门禁后才允许 matcher 自动消费；
5. 护栏 `guard_killed_correct=0` 且长期无收益后再退役旧正则。

## 9. 最终建议

不建议推翻现有架构，也不建议在此时引入 CRF、多层 NER、复杂 loss 或更大的基座。
当前风险主要来自评估可信度和数据边界，而不是模型容量。

最优先的投入顺序应当是：

1. gold 与切分；
2. 重叠标签和剩余裁决；
3. 可执行的端到端门禁；
4. 三种子正式训练；
5. shadow 后再让 matcher 自动消费。
