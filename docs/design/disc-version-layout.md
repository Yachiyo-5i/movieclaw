# 原盘目录与多版本摆放规范（入库落点避让）

> 状态：设计定稿，待实施。
> 关联：docs/design/quality-upgrade.md（洗版）、docs/design/library-file-recycle.md（回收）、
> docs/design/library.md（媒体库总纲）。

## 1. 背景：生态调研结论

主流媒体库软件（Jellyfin / Emby / Kodi / Plex / tinyMediaManager）对原盘目录
（BDMV / VIDEO_TS）的摆放约定高度一致：

1. **单原盘的规范形态是"电影文件夹本身就是原盘"**——条目目录直接包含
   `BDMV/` 或 `VIDEO_TS/`（Jellyfin/Emby/Kodi 官方文档的标准示例）：

   ```
   Movies/
   └── 阿凡达 (2009)/
       └── BDMV/...
   ```

2. **没有任何一家支持"同一文件夹内多版本含原盘"**。Jellyfin 官方文档明确：
   "VIDEO_TS 或 BDMV 文件夹不支持多版本、多部分或外挂字幕/音轨"；
   tinyMediaManager 评估后明确决定不实现。多版本命名约定
   （`文件夹名 - 标签.ext` 严格前缀）只对普通视频文件生效。

3. **原盘参与多版本的通行答案是"每个版本一个独立的电影级文件夹"**
   （tinyMediaManager 官方推荐形态，也是唯一对原盘结构/ISO/分段文件
   全兼容的方案；Plex 的 `{edition-}` 后缀同样支持每版本独立文件夹）：

   ```
   Movies/
   ├── 阿凡达 (2009)/                ← 文件版本（可多个，同目录 - 标签命名）
   └── 阿凡达 (2009) - 4K原盘/       ← 原盘版本，独立同级目录
       └── BDMV/...
   ```

由此推出本设计的核心矛盾：**扁平形态（条目目录=原盘）是生态规范形态**，
而 movieclaw 的入库落点 `derive_save_path` 恒为 `主根/标题 (年份)/`——
原盘影片触发洗版时，新文件必然硬链进原盘目录**内部**。这不是边缘场景，
是规范摆放下洗版的必然路径，会连锁引发三个问题：

- 下游播放器不认"原盘目录内部的文件"（Jellyfin 视条目目录为原盘整体）；
- 库扫描遇到原盘目录只记目录本身、不进入内部遍历（`_walk_videos`），
  内部文件行永远不在 seen 集合里，收尾缺失判定会把在盘的行误标缺失，
  且缺失标记永远不会自愈（复活依赖扫描按路径重新命中）；
- 旧原盘清理时 rmtree 的爆炸半径盖住新文件（recycle 已加台账保护兜底，
  但兜底触发意味着用户必须手工解困）。

## 2. 规范定义（movieclaw 采纳的摆放约定）

| 形态 | 摆放 | 说明 |
| --- | --- | --- |
| 单文件版本 | `标题 (年份)/标题 (年份).ext` | 现行入库命名，不变 |
| 多文件版本 | `标题 (年份)/标题 (年份) - 标签.ext` | 现行冲突退让命名（`_resolve_transfer_target`），与 Jellyfin/Emby 多版本约定一致，不变 |
| 单原盘 | `标题 (年份)/BDMV/…`（扁平） | 生态规范形态，扫描正常收编，不变 |
| 原盘 + 其他版本 | 原盘独立同级目录 `标题 (年份) - 标签/BDMV/…`，文件版本照常落条目目录 | **新增约定**：入库落点避让（§3） |

台账模型天然兼容：版本共存的单位是 MediaItem 下的多条 LibraryFile 行，
识别链按片名+年份归并，与文件在哪个目录无关。同级版本目录的行与条目目录
的行归并到同一条目，详情页文件区照常并列展示。

**明确不做**："条目目录内嵌套原盘子目录"（`标题 (年份)/xxx.BluRay/BDMV`）
不作为推荐规范——movieclaw 能识别，但用户拿同一个库喂 Jellyfin 时该版本
会被当作附属内容丢弃。存量这么摆的库不干预（扫描照常收编），文档与
社区指引统一引导到同级版本目录。

## 3. 入库落点避让（核心改动，ingest）

### 3.1 行为

监听导入解析出目标条目目录 `dest_dir = 主根/标题 (年份)` 后，增加一步
**物理判定**（不依赖台账，`is_disc_dir`：目录下存在 `BDMV/` 或
`VIDEO_TS/` 子目录）：

```
dest_dir 不存在或不是原盘目录 → 照常落条目目录（绝大多数路径，零变化）
dest_dir 是原盘目录           → 落同级版本目录 主根/标题 (年份) - {标签}/
```

- 标签取值与 `_transfer` 的版本标签同源：`spec.resolution`（主文件探测）
  → `release_attrs.media_source` → `"V2"`，经 `sanitize_folder_name` 清洗。
  电影主文件探测在落点解析之前已经完成（探测门禁），标签总是可得；
- 版本目录内的文件命名照常走 `entry_base_name + 冲突退让`，即
  `标题 (年份) - 2160p/标题 (年份).mkv`——目录级已带标签，文件级不必
  重复（Jellyfin 单文件夹单文件的识别不要求文件名前缀匹配）；
- 版本目录已存在 → 直接使用（文件级冲突退让兜底）；版本目录本身又是
  原盘目录（用户手动摆了同名原盘）→ 追加数字后缀 ` - {标签} (2)`，
  拒绝无限递归；
- 电影与剧集同一逻辑（剧集条目目录是原盘的场景极罕见，但处理无成本：
  Season 子目录照常建在版本目录内）；
- 自定义目录（staging）不适用：过客文件不与库内原盘同目录。

### 3.2 为什么判物理不判台账

台账里的原盘行（`container in ("bluray", "dvd")`）依赖扫描先行收编；
用户刚手动摆好原盘、扫描还没跑，此时入库落点若只查台账会误落进去。
物理判定 `is_disc_dir` 一次 stat 的成本，覆盖账实不一致的窗口期。

### 3.3 实施位置

- `_is_disc_dir` 从 `scan.py` 迁至 `layout.py` 公开为 `is_disc_dir`
  （layout 的既有职责就是"避免 scan ↔ ingest 循环导入的公共约定"），
  scan 侧保留引用；
- `ingest.py` 目标目录解析处（`derive_save_path` 调用点之后）插入避让；
- 洗版无需专门改动：洗版下载与首次入库走同一条监听导入链路，落点避让
  对两者同时生效。

## 4. 扫描口径：原盘内部行的精确对账（存量兜底）

落点避让保证 movieclaw 不再制造嵌套，但嵌套行仍可能存在（本功能上线前
产生的、用户手动放进去的）。这些行扫描永远看不见（`_walk_videos` 不进
原盘目录），现行收尾缺失判定按 seen 集合会误标缺失、且永不自愈。

改动：收尾感知删除循环中，**路径位于任一原盘行之下**的行改按物理存在性
对账（原盘行集合从本轮台账快照按 `container in ("bluray", "dvd")` 收集，
前缀匹配）：

```
IN_PLACE + 文件存在   → 保持（现行为：误标缺失）
IN_PLACE + 文件不存在 → 标缺失（与现行为一致，只是判据换成 stat）
MISSING  + 文件存在   → revive（现行为：永不自愈）
MISSING  + 文件不存在 → 保持缺失，交自动清理
```

嵌套行数量极少（正常库为零），逐行 `stat` 成本可忽略；TRASHED 行不参与
（回收机制自管）。

## 5. 现状已达标、无需改动的部分（核对清单）

| 能力 | 现状 | 结论 |
| --- | --- | --- |
| 多文件版本命名 | `_resolve_transfer_target` 冲突退让 `- 标签` | 已符合 Jellyfin/Emby 约定 |
| 版本目录识别归并 | 识别链按片名+年份归并到同一 MediaItem | 天然支持，补用例（§6） |
| 条目删除覆盖版本目录 | `delete_item_files` 逐行收集条目目录（`entry_dir_of`），同级版本目录逐个进入 `dirs_to_remove` | 已覆盖，补用例 |
| 原盘回收 | 目录一律原地待回收（改名断种）；purge 有台账爆炸半径保护 | 已完备（recycle 设计 §7） |
| 原盘洗版基线 | `disc_main_stream` 探测主流文件 | 不变 |
| 库根迁移 | transfer 按相对路径搬运，版本目录随行 | 不变 |

爆炸半径保护（recycle/purge 与 delete_single_file 的"目录下还有其他在案
文件行则拒删"）**保留不撤**：它是存量嵌套与用户手动嵌套的最后防线，
落点避让只是让它在新增数据上永远不被触发。

## 6. 测试清单

1. ingest：条目目录是原盘 → 新文件落 `标题 (年份) - {标签}/`，台账行
   归并到同一 MediaItem；条目目录正常 → 落点不变（回归）；
2. ingest：版本目录已存在（二次洗版同标签）→ 复用目录 + 文件级退让；
3. 识别：`标题 (年份) - 4K原盘/BDMV` 与 `标题 (年份) - 2160p/x.mkv`
   目录名的片名/年份提取归并用例；
4. 扫描：原盘内部的存量行——在盘不标缺失、缺失后回归自动 revive、
   真消失标缺失；
5. 删除：条目含同级版本目录 → 整删覆盖所有版本目录（含原盘版本目录）；
6. 洗版端到端（现有用例回归）：原盘基线 → 文件版本入库 → 旧原盘
   原地待回收 → purge 不再命中爆炸半径保护。

## 7. 落地顺序

1. `is_disc_dir` 迁移至 layout + ingest 落点避让 + 测试 1/2/3；
2. 扫描存在性对账 + 测试 4；
3. 删除/洗版交叉用例 5/6 + 文档（本文标记已实施、library.md 摆放规范
   一节补链）。

每步独立可合并，功能开关不需要：避让只在"条目目录是原盘"时生效，
对既有库零影响。
