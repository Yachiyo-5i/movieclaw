# AI 外挂字幕生成：找源 → 翻译 → 落盘为 sidecar 的完整机制

> 状态：设计 v1（2026-08-10），待评审。
> 源起：用户提出（2026-08-10）——目标语言字幕缺失时，用已集成的 LLM
> 从内封/外挂现存字幕里找最优参考，按影片与对白风格翻译成目标语言；
> 远期无任何字幕源时走音轨识别（ASR）。
> 前置：[jellyfin-subtitle.md](jellyfin-subtitle.md)（外挂字幕台账/发现/
> 输出/播放控制已全量落地）——本设计是它的**生产端**，只造文件，
> 消费端零改动。
> 关联：movieclaw_llm（LLM 接入层）、[metadata.md](metadata.md)（影片
> 元数据是风格 prompt 的素材）。

## 0. 核心裁决：产物就做成外挂字幕文件

**是。写成视频同目录的 sidecar（`<stem>.<目标语言>.ai.srt`）是唯一
正确形态**，四条理由：

1. **消费链路零改动全自动生效**：文件落盘 → watchdog 字幕事件 → 台账
   重发现 → PlaybackInfo 外挂流（带 DeliveryUrl）→ 播放器可选可显、
   编码归一与格式转换照走——jellyfin-subtitle.md 建成的整条链路直接
   吃到，生成机制不需要碰 B/C 层任何一行代码；
2. **文件即资产**：跟着视频走（搬库/整理同迁）、用户可用任何工具编辑
   修正、迁回真 Jellyfin/Emby 或换任何播放器都仍然可用——不锁在
   movieclaw 的数据库里；
3. **回退零成本**：不满意删文件即可，下轮扫描台账自动消失；重新生成
   就是覆盖写同名文件；
4. **与"库存事实"模型自洽**：台账（external_subtitles）的语义是"目录里
   有什么"，AI 产物落成目录里的真实文件后自然入账，不需要第二套
   "虚拟字幕"记账体系（那会让台账三态、可见性、缓存失效全部翻倍）。

命名约定：`<video stem>.<语言token>.ai.<ext>`（如
`Movie.2024.chs.ai.srt`）。`ai` 不入语言表和旗标表，按既有解析规则落进
`title`——DisplayTitle 显示为 `"Chinese - ai - SUBRIP - External"`，用户
在播放器里能一眼区分 AI 字幕与人工字幕；同时它是管线自己的幂等标记
（已生成过的目标语言不重复生成，重生成=覆盖同名文件）。

## 1. 三级来源瀑布

```
① 现存字幕翻译（本设计主体）
   台账外挂 + 内封文本轨 → 选最优参考 → LLM 分块翻译 → sidecar
② 音轨识别（远期 P3，本文只定接口位）
   无任何文本字幕源 → ASR 出原语言字幕 → 进 ① 的翻译管线
③ 在线字幕站点（不做）
   Infuse/VidHub 自带在线字幕；服务端接字幕站生态此前已裁决不做
   （jellyfin-subtitle.md §1），本设计不推翻
```

## 2. 源选择：规则打分，不用 AI

"找准确率最高的参考"不需要 LLM 参与——决定参考质量的因素全部是
结构化事实，规则打分即可（省一次调用，且可解释可测试）：

候选池 = `external_subtitles`（文本外挂）∪ `subtitle_streams` 中的
文本内封轨（`srt/ass/ssa/subrip/webvtt/mov_text` 等；PGS/VobSub 图形轨
排除——OCR 不做，见 §8 不做清单）。打分维度按权重从高到低：

1. **排除项**：forced 旗标（外语片段部分字幕，几百条对话缺失，绝不能
   当翻译源）；目标语言自身（已有目标语言字幕时任务本就不该发起）；
2. **语言优先**：影片原语言（`media_metadata` 可得 original_language）
   最优——原语言字幕是"第一手台词"，其他语言字幕已经是一次翻译，
   二次转译误差叠加；其次英语（字幕组世界的通用中间语言）；
3. **完整度**：解析后的对话条数与覆盖时长比（首末事件跨度/影片时长）
   ——防止选中残缺轨；内封轨条数未知时先抽取再评估（§4）；
4. **形态**：外挂优先于内封（免抽取一步）；sdh 可用但翻译前清理
   `[音效]`/`(拟声)` 类标记；ass 可用（只取对白文本）。

平分时取序在前者（决定性）。选源结果与打分明细落任务日志——用户要能
看懂"为什么选了这条"。

## 3. 翻译管线（LLM 核心环节）

### 3.1 分块与上下文

- pysubs2 解析参考字幕 → 对话事件序列（时间轴 + 文本）；
- **按事件数分块**（每块 ~40-60 条），块间带**滚动上下文**：上一块的
  末尾 N 条原文+译文一起入 prompt——跨块的对话连贯性靠它（角色称谓、
  上下句衔接）；
- 全片**术语表两遍法**：第一遍快速扫全文（或抽样）让模型抽取人名/
  地名/专有名词并给出统一译名，第二遍逐块翻译时把术语表钉进 system
  prompt——同一个角色名整片一致是字幕质量的硬指标；
- 影片风格素材入 system prompt：标题/年代/类型/简介（媒体库元数据
  现成）+ 明确指令"保持台词口语化、贴合角色语气、不过度书面化"。

### 3.2 结构化输出与校验（防幻觉的硬约束）

- 请求体给**带序号的原文清单**，要求返回同序号的译文清单（JSON），
  **时间轴完全不经过模型**——模型只见文本，时间轴由管线原样保留，
  从机制上杜绝时间漂移；
- 逐块校验：返回条数=输入条数、序号连续；不符重试该块（至多 2 次），
  仍失败该块保留原文并记告警——**出错的块保留原文也比整任务失败强**；
- 行长后处理：中文按 ~20 字/行折行（规则处理，不劳模型）；
- 输出 v1 恒为 **srt + UTF-8**（最大公约格式；参考是 ass 时只翻对白，
  样式不迁移——样式迁移收益低、幻觉面大，列不做）。

### 3.3 任务形态：可恢复、可取消、有成本护栏

- 长片 1500+ 条对话 ≈ 30-40 个块，任务分钟级——必须是后台任务：复用
  `task_state` 基建，进度=已完成块数/总块数，可取消；
- **断点续传**：已译块暂存 `data/cache/subtitle_gen/<file_id>.<lang>.json`
  （逐块追加），任务中断/失败后重发从断点继续——LLM 调用是真金白银，
  已花的钱不能作废；成功落盘 sidecar 后清理暂存；
- 成本护栏：任务发起前按事件数估算 token 量并在确认框展示；全局并发
  =1（队列串行），单任务失败块超阈值（>20%）自动中止；
- LLM 调用经 `movieclaw_llm.router`（供应商/模型由现有 LLM 设置域
  决定），限流与重试沿用接入层语义，`LlmRateLimitError` 退避续跑。

## 4. 内封轨抽取（兑现 jellyfin-subtitle.md §6.4 的预留）

选中的参考是内封轨时，先抽成临时文本文件再进管线：

- `ffmpeg -i <video> -map 0:s:<k> -c:s srt <tmp>`（文本轨转 srt）——
  沿用 media_probe 的直接 subprocess 风格，线程池执行、超时保护、
  失败中文日志；不引 ffmpeg-python；
- `0:s:<k>` 的 k 就是 `subtitle_streams` 数组下标（与中性引用
  `embedded:<k>` 同源，ffprobe 输出序即 ffmpeg 字幕流序）；
- 抽取产物进 `data/cache/subtitle_gen/`，任务结束清理——它是中间品，
  不是资产，不落库目录；
- strm 条目没有本地视频本体：内封轨不可抽取，候选池只有外挂
  （云播放场景恰好外挂就是主形态，影响有限，任务发起时如实提示）。

## 5. 触发形态

| 入口 | 期 | 说明 |
|---|---|---|
| 手动：条目/版本详情页"生成字幕"（选目标语言，默认中文） | P1 | 主入口。发起前展示选源结果与成本估算，确认后入队 |
| 手动重生成 | P1 | 覆盖写同名 sidecar；台账由 watchdog/扫描自动刷新 |
| 自动：入库后检测目标语言缺失即生成 | P2 | 库级开关**默认关**——批量入库=批量 LLM 消费，必须用户显式授权；沿用"资源管控三件套"范式做开关与额度 |
| ASR 兜底 | P3 | 见 §7 |

产物落视频同目录；目录只读（只读挂载）时写失败给明确中文错误，
不做库外落位兜底（第二条路径破坏"外挂=同目录"约定，见开放问题 1）。

## 6. 分层归属（对齐既有架构）

| 能力 | 层 | 模块 |
|---|---|---|
| 选源打分、内封抽取、翻译管线、任务编排 | A 媒体库（生产端服务） | `movieclaw_api/services/subtitle_gen/` |
| LLM 调用 | LLM 接入层 | `movieclaw_llm.router`（现成） |
| 字幕解析/写出 | 复用 | pysubs2（已入依赖） |
| 发现/台账/输出/播放控制 | 已建成 | **零改动**——sidecar 落盘即被消费 |

翻译管线不 import `movieclaw_jellyfin` / `movieclaw_playback`——它是
纯生产端，与播放两层互不感知（守护测试同款断言）。

## 7. ASR 远期（P3，只定接口位）

- 形态：`SubtitleSource` 抽象的第三个实现（现存外挂/内封抽取之外），
  产出"原语言 srt"后**汇入同一个翻译管线**——ASR 与翻译解耦，英语片
  ASR 产物本身就可直接落盘；
- 技术候选：faster-whisper（CTranslate2，CPU 可跑但 2 小时片实转
  数十分钟起）或 OpenAI 兼容的转写 API（走现有 LLM 供应商体系）。
  本地模型可沿用 NER 模型的"GitHub Release 下载、不进包"分发惯例；
- 不在本期展开：CPU 推理时长、VAD 断句质量、音轨选择（多音轨选原语言）
  都需要单独调研，先把 §3 管线的输入接口留成"任意 srt 事件序列"即可。

## 8. 不做清单

| 不做项 | 理由 |
|---|---|
| PGS/VobSub 图形字幕 OCR 做翻译源 | OCR 引擎重、错字进翻译二次放大；有文本源的片子占绝对多数 |
| ass 样式迁移/双语字幕合成 | 样式迁移幻觉面大；双语=两轨各自可选，播放器本就支持多轨切换 |
| 服务端接在线字幕站点 | 既有裁决（jellyfin-subtitle.md §1），播放器自带 |
| LLM 参与选源 | 结构化事实规则可判，省调用、可解释、可测试 |
| 翻译产物入库不落盘 | 违背"文件即资产"与台账语义，见 §0 |

## 9. 分期与验收

| 期 | 内容 | 验收 |
|---|---|---|
| G1 | 选源打分 + 内封抽取 + 翻译管线（分块/术语表/校验/断点续传）+ 手动触发任务 | 单测:打分矩阵（forced 排除/原语言优先/完整度）、分块与校验（条数不符重试/超阈值中止）、断点续传;手测:整片翻译落盘后 Infuse 可选"Chinese - ai"字幕且时间轴精确 |
| G2 | 入库自动生成开关（默认关）+ 额度护栏 + 控制台任务视图 | 手测:批量入库不触发（开关关）;开后逐条入队且额度熔断生效 |
| P3 | ASR 源 | 单独设计后实施 |

## 10. 开放问题

1. 只读库目录的产物落位（库外 data/ 落位会引入"第二路径"，需要台账
   与服务层同时扩展——有真实用户诉求再议）；
2. 翻译质量评估的自动化（抽样回译比对？）——G1 先靠人工验收；
3. 多版本条目（同片多文件）是否共享翻译产物——时间轴可能因版本
   剪辑不同而错位，v1 按"每个文件各自生成"处理，不做跨版本复用。
